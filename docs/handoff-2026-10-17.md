### 2.2 Claude 経路・コスト
- **19 万トークン問題(修正済み `3f54f5a`)**: Codex の `apps` feature が既定で有効で、ChatGPT にサインインしていると `codex_apps` MCP サーバーの全コネクタ tool 定義を要求に入れる。Claude のモデルは Codex に未知で fallback metadata の `supports_search_tool: false` → tool が遅延されず全文(`core/src/mcp_tool_exposure.rs` `ToolExposure::Direct`)。GPT 経路では遅延されるので表に出なかった。`features.apps/plugins/tool_suggest=false` で 238,468 → 30,943 トークン。
- 残りの 3 万トークン = base 26KB + developer 29KB + AGENTS 20KB + Struis の tools。Linux で同じ Codex バイナリに同じ `thread/start` を渡した replica で 91KB、実機の数字と一致。
- **Codex の再試行**: 400 だけ再試行しない(`codex-api/src/api_bridge.rs` → `InvalidRequest`)。401・5xx は `request_max_retries(4) × stream_max_retries(2)` = 15 回送り直す。プロキシの App Attest 失敗は 400 で返すように修正済み(`1e32e61`)。
- **App Attest**: Console の App integration は Team ID + Bundle ID 一覧に紐づく。prototype の Bundle ID(`com.digiloglab.strius.preview.sNN`)は Console に追加が必要(s05 は追加済み)。Apple の仕様で鍵は入れ直し・移行・復元で消えるが Keychain の ID は残る。実機は `DCError.invalidInput(2)` を返した。`serverUnavailable` 以外の DCError で鍵を作り直すように修正済み。
- **プロンプトキャッシュ**: TTL 1h。エージェントの実行は 3〜4 時間なので、1 時間以上空いた再開ではセッションを復元してもキャッシュは効かず、履歴全量を書き直す。復元が得なのは中断直後(1 時間以内)の自動再開だけ。
- 新しいスレッドごとに `cache_read 0`(3 万トークン書き直し)。原因未調査。
- 1 ターンに `turn_start → continuation → validation_repair → continuation …` が 6 要求続いた例あり(上限なし)。

### 2.3 描画
- `ChatTimeline.swift` には「数式 WebView の高さが後から決まる」ことへの補正が 6 つ(`scrollPosition(.bottom)`、`defaultScrollAnchor`、`scrollToEnd` 送り直し、`follow` 送り直し、`KaTeXPrefetcher`、`ChatAnchorKeeper`)。送信時の揺れは送り直し同士の取り合い(修正済み `540ca40`、実機未確認)。
- SwiftMath(iosMath の Swift 版)で、台帳・フィクスチャ・配信プロンプトから抜いた数式 260 個・コマンド 19 種は未対応 0(`\bad`・`\cd` はテスト用の無効コマンド)。未対応: `\boxed` `\underbrace` `\overbrace` `\overset` `\underset` `\because` `\therefore` `\middle` `\:`。Claude/ChatGPT の iOS アプリも SwiftMath/iosMath を同梱。→ Issue #28。

### 2.4 学習設計(10/17 朝の実使用)
- 小単元「三角関数の直交性と積分計算」: 例題 ∫x sin x、類題 1 問、演習 10 問中 例題と同じ型は 4 問。残りは部分積分 2 回・一般の n・2 乗の展開・判定・説明。合格線 8/10。
- 原因: `set_instructions.md` の「comparable difficulty(基準なし)」「vary how each problem asks … check the answer, change the context」。練習段階が「例題 1 → 類題 1 → 10 問の試験」で公式を定着させる段が無い。
- 演習の第 1 問が `prompt: ""`、`answer_key: ""` のまま `set.filled` に入った(アプリの検証不足)。
- 採点が、要点で教えた近道(直交性で直接 0)に対して積和の途中式を要求した。
- 設計上の結論(人の判断): 段階を増やすのではなく「例題の水準 = 演習の水準」にし、要点の情報(公式・使ってよい定理)に解いている最中に届くようにし、演習の中でゆっくり上げる。仕様は今日の穴からではなく「よい個別指導が各段階で何をするか」から書く。対象は「紙で示せて採点できる積み重ねの技能」で、中高・大学を分けない(レポート型は対象外)。

### 2.5 運用
- 人が prototype で毎回検証する運用は勉強を止めるので持続しない。勉強用(枠 A)と検証用(枠 B)を分け、失敗時の診断は自動化する方針。
- AI が自力で見つけられなかった理由は、実機と台帳が AI に届いていなかったこと、品質の計器が無かったこと、「CI を緑に」以外の目標が与えられていなかったこと。

## 3. 決めたこと(設計判断)

1. **基盤(UI と CI)を最初に直す。** 数式 WebView が揺れ・CI の 35 分・不安定テストの共通原因なので #28 が先、その数字で CI を設計する。それまで他の機能修正を main に積まない(積むたびに不安定な CI を通すことになる)。
2. エージェントの自動再開は残す。ただし検証失敗からの再開は「同じ HEAD の CI を緑にする」以外をさせない。人の指示での再開は新しいセッション(Issue スレッドを文脈に)。復元は中断直後だけ。
3. PR の合格条件は「走ったものは全部緑」。全件 UI テストを PR ごとの門にするかは、#28 後の全件時間を見て決める。skip・期待失敗化・判定緩和・Re-run で緑にするのは禁止。
4. 学習設計の仕様を 1 本書き、プロンプトとアプリの段階定義との差分一覧を出してから直す。
5. `agentctl.py` は縮める(セッション保存・復元、`state.json`、使用量表の大半をやめ、reaction・ラベル・`gh` で置き換える)。言語の問題ではなく、やることが多すぎる問題。

### 1.1 で分かったこと(再発防止の根拠)

- SwiftUI は吹き出しに付けた `accessibilityIdentifier`(`assistant-message-…`)を子要素にも広げ、子に付けた識別子を上書きする(`DeviceChatUITests` はこの性質に依存している)。数式の行(`UIScrollView`)・段落(`UILabel`)に付けた `math-display`・`math-text` は UI テストから見えない。`ChatScrollStabilityUITests` は吹き出しの中の `scrollView` を要素の型で探す。原因は 8 回目の CI で要素の木を PROBE に出して確定した。
- UI テストから画面の写真と要素の木を取る経路: `STRUIS_PROBE_DIR`(ios.yml が `TEST_RUNNER_STRUIS_PROBE_DIR=$RUNNER_TEMP/ui-probe` で渡し、artifact `ios-test-results-*` に入れる)。`ChatScrollStabilityUITests.saveProbe` が例。xcresult の中の添付は Linux のセッションからは読めない(内部形式)。

- SwiftMath は数式の中の ASCII 以外の文字(`≒`、`α`、日本語)を**黙って捨てる**(`MTMathAtomFactory.atom(forCharacter:)` が nil → `MTMathListBuilder` が読み飛ばす)。`\text{…}` の中だけ受け付ける。だから正規化で記号は命令に、残りは `\text{}` に包む。
- `MTMathImage.asImage()` は高さが fontSize/2 未満の数式(`-`、`\ldots`)を fontSize/2 の中央に寄せて描くが、画像の高さは ascent + descent のままで下にはみ出す(空の画像になる)。下の余白を足して直した。
- SwiftMath に無い書き方で多いのは `\dots`(→ `\ldots`)、`align`(→ `aligned`)、`\tag`、`\therefore`/`\because`(→ `\text{∴}`)、`\fallingdotseq`(→ `\text{≒}`)。残る未対応は `\boxed`・`\underbrace`・`\overbrace`・`\overset`/`\underset`・`\stackrel`・`\cancel`・`\middle`・`\xrightarrow`・`array` 環境。
- `struis-math.js` の `!=` → `\ne`、`<-` → `\leftarrow` は `n!=n(n-1)!`(階乗)と `x<-1` を壊していた。Swift 側では階乗と空白なしの `<-` を変換しない。
- `MTTypesetter.createLineForMathList` は public ではない。描画は `MTMathImage`、高さ・基線の計測は画面外の `MTMathUILabel.displayList` で取る。
- Linux でも SwiftMath の解析器(`MTMathList`・`MTMathAtomFactory`・`MTMathListBuilder`・`MTUnicode` + `NSException` の shim)だけなら `swiftc` で組めて、数式の対応表の確認が CI なしでできる(手順: swift.org の Linux toolchain を展開し、4 ファイルと `MathSourceNormalizer.swift` を直接 `swiftc` に渡す)。
