# 知識グラフを作る・見直す(タイムライン)

この学習者だけの知識グラフを作ります。点は「できること」、線は「○○を解くには××が要る」(prerequisite)か「○○でよくある勘違い」(misconception)です。全員に共通のグラフではありません。

入力は1つの JSON です。`task` が `build`(最初に作る)、`extend_unit`(新しい単元の分の点と線を足す)、`review`(丸ごと見直す)のどれかです。

## 点

- `id` は `単元.名前` の英小文字とアンダースコア(例: `quad.vertex_form`)。一度付けた ID は変えない(記録はすべて ID に紐づく)。
- `kind` は procedure(手順)・concept(概念)・combination(組み合わせ: 2つを使って説明・解けること)・memorized(暗記事項)。
- `name` は学習者に見せる短い名前(例: 平方完成)。同じ「できること」を言い回し違いで別の点にしない。
- 単元の目標から前提へ、1つ下の学年まで下りる(中学の一次関数や展開でつまずく人の行き先を用意する)。

## 線

- `from` が前提の側、`to` がそれを使う側。存在しない点への線、前提がぐるぐる回る線は作らない(アプリが点検して、あれば受け取りを断る)。
- misconception の線は `from` = `to` = その点にして、`note` に勘違いの中身を書く。

## build / extend_unit

`nodes` と `edges` を返す。`ops` は空。`start_node_id` には、目標から前提の方へ数段下った真ん中あたりの点を入れる(初回の位置決めをそこから試す)。採点結果(`attempts`)があれば、それと矛盾しないようにする。

## review

グラフ全体を書き直さず、`ops`(操作の列)だけを返す。`nodes` と `edges` は空。

- add_node・remove_node・split_node(1つを `into` の2つに分ける)・merge_nodes(`node_ids` を `into` の1つにまとめる)・add_edge・remove_edge。
- 操作ごとに、根拠の答案(attempt の ID)を `evidence` に入れ、`reason` を1行で書く。
- 別々の日の間違いに同じ原因がないかを見る(例: 「切片を求める」と「傾きを求める」の両方で負の数を間違えている → 両方の前に「負の数を含む計算」を置き、分けた点を元に戻す)。
- 分けた・まとめた点の記録は、アプリが引き継ぐ。
