# 知識グラフを1段ずつ分解する(タイムライン)

この学習者だけの知識グラフを、上から1段ずつ作ります。点は「できること」、線は「○○を解くには××が要る」(前提)です。全員に共通のグラフではありません。

入力は1つの JSON です。`nodes` が、まだ前提を調べていない点です。`mode` は `build`(初めて開いた時)・`extend`(新しい単元)・`step`(前の段の続き)・`descend`(生徒を教えているモデルが、その1点の直前の前提を知りたいと判断した。理由は `reason`)のどれかです。`unit_context` は今の単元と小単元、`existing_nodes` は既にある点の一覧です。一番上の点(小単元の到達目標)には `goal` があります。

## 答えること(この3つだけ)

`nodes` の点ごとに、`items` を1つ返します(`node_id` はその点の ID)。

1. `problem`: その「できること」の典型的な問題を1問書く。
2. `steps`: その問題を解く手順に分けて書く(`text`)。手順ごとに、その手順で使う、より小さい「できること」を `uses` に挙げる。
3. `uses` の点は、`existing_nodes` から選べるものはその `id` と `name` をそのまま使う。無いものだけ新しい ID を付ける。

## 点の大きさ

- 「その点だけを使う問題が1問作れて、○×がつけられる大きさ」にする。大きすぎる点(「二次関数ができる」)も、小さすぎる点(「2 を書ける」)も作らない。
- 同じ「できること」を言い回し違いで別の点にしない。迷ったら `existing_nodes` の点を使う。
- 新しい `id` は英小文字・数字・`.`・`_` で、`分野.名前`(例: `quad.vertex_form`、`trig.derivative_sin`)。`name` は学習者に見せる短い日本語(例: 平方完成)。
- `kind` は procedure(手順)・concept(概念)・combination(2つを使って説明・解けること)・memorized(暗記事項)。

## 今の単元の中か、前に習う内容か

- `in_unit` は、その点が今の単元(`unit_context`)で新しく習う中身なら true、それより前に習う内容なら false。
  - 例: フーリエ級数の単元なら、係数の式・級数で書くことは true。sin・cos の微分、積の微分、加法定理、sin kπ・cos kπ の値は false。
- true の点は、次の段でアプリがさらに分解を頼みます。false の点は置くだけで、今は掘りません(学習者がそこで × を続けた時だけ、1段下ります)。
- `mode` が `descend` の時は、その1点の直前の前提だけを挙げる(さらに下は書かない)。`in_unit` は false でよい。

## してはいけないこと

- 渡した点そのものを `uses` に入れる、前提がぐるぐる回るようにする(アプリが点検して、その線だけを捨てます)。
- 他の点を経由して届く遠い前提を、直接の前提として挙げる(直前の前提だけを挙げる。アプリが点検して消します)。
- よくある勘違いを書く(形が決まった後に別に頼みます)。

`notes` には、迷った所を1行で書く(無ければ空)。
